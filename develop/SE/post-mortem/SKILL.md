# post-mortem

Use the known symptom, causal mechanism, fix pointer and actual validation. Distinguish confirmed facts from unknowns. If the cause is unresolved, write an investigation record rather than pretending the incident is closed.

Keep summary, cause, fix and validation short. Add timeline/impact for incidents and prevention actions only when supported by evidence. Record how the test gap arose without blaming people. Do not invent owners, metrics or tests.

Save to the requested repository/document destination; posting to tickets or sending messages requires existing user authorization. A trivial typo fix does not need a post-mortem. No dependency on a ticket system or another skill.
